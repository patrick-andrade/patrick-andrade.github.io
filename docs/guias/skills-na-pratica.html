Skills na Prática

O que é uma skill, quando vale criar uma e como o agente a encontra.

Versão: 0.3.0
Leitura essencial: cerca de 5 minutos

Não tem mágica nenhuma. Uma skill é um diretório com um arquivo SKILL.md dentro: um cabeçalho com nome e descrição, e um corpo de texto que é, essencialmente, um prompt bem escrito sobre como executar uma tarefa. Às vezes acompanha um scripts/ com scripts de apoio, pra que o LLM não precise recriar do zero toda vez.

Skills são só prompts.

É só isso. Um prompt que você versionou, refinou, e deixou a um comando de distância. A única diferença entre uma skill e aquele prompt gigante que você cola no chat todo dia é que a skill mora num arquivo, com nome, e o agente sabe que ela existe.

Um bom agente de IA consegue montar o SKILL.md a partir do procedimento. Este guia mostra o que a pasta é e quando vale a pena ter uma. Não é um formulário para copiar.

Quando vale criar

Crie uma skill quando a mesma tarefa volta, com as mesmas fontes, etapas e checagens. Aí repetir o prompt inteiro custa tempo e o resultado oscila.

Não vale para uma preferência de uma linha, uma tarefa que você faz uma vez ou uma coleção sem fronteira.

O que vai no arquivo

O arquivo obrigatório é o SKILL.md. A forma é esta:

---
name: revisar-guia
description: Revisar um guia prático antes de publicar.
---

1. Identifique o público e o resultado.
2. Separe fato, decisão editorial e inferência.
3. Confira links, exemplos e o que pode ir ao repositório público.

O nome diz o que é. A descrição diz quando usar. O agente encontra a skill pela descrição.

O resto do diretório é opcional:

minha-skill/
├── SKILL.md
├── scripts/
├── references/
└── assets/

Use scripts/ para operações que se repetem iguais. Mova tabelas longas e exemplos para references/. O agente lê nome e descrição primeiro; o corpo e os anexos só entram se a skill for usada.

Uma skill útil responde, nesta ordem: que resultado produzir, quando usar e quando não usar, quais fontes valem, que sequência seguir, onde você precisa decidir, e como conferir a saída.

Use verbos que se observa: “extraia”, “compare”, “renderize”, “confira”. “Faça bem” sem um teste não ajuda.

Onde ela mora

No repositório:

meu-projeto/
└── .agents/
    └── skills/
        └── revisar-guia/
            └── SKILL.md

O Codex procura .agents/skills da pasta de trabalho até a raiz do projeto. Skills pessoais podem ficar no diretório de skills do usuário. Plugins servem para distribuir um conjunto maior.

No Codex CLI e na IDE, liste com /skills ou chame com $nome-da-skill. No ChatGPT, dá para escolher com @. Se o pedido combina com a descrição, o agente também pode ativá-la sozinho.

Depois de criar ou instalar, abra uma nova tarefa se a interface ainda não listar a skill.

Um procedimento de exemplo

Se você publica guias, a skill guarda o fluxo, não a apostila que você estudou:

  • classificar o texto como guia rápido ou estudo de caso;
  • declarar problema, pré-requisitos e premissas;
  • explicar o mecanismo antes da receita;
  • rodar um exemplo realista;
  • mostrar resultado e limites;
  • citar fontes atuais;
  • revisar o que pode entrar no repositório público.

Peça ao agente para transformar esse fluxo num SKILL.md. Depois leia o arquivo e ajuste o que ele errou.

Teste antes de confiar

Faça pelo menos três ensaios:

  1. pedido direto: a skill deve ser encontrada e aplicada;
  2. pedido vizinho: ela não deve assumir um escopo maior do que o pedido;
  3. caso incompleto: ela deve pedir ou achar a fonte, sem inventar.

Depois, confira se o resultado ficou melhor do que com um prompt curto, se as instruções não brigam com o AGENTS.md, se os scripts falham de um jeito compreensível, se as referências não têm credencial nem caminho pessoal, e se a skill não promete permissão que o ambiente não dá.

Manutenção

Versione mudanças que alteram o comportamento. Quando a ferramenta mudar, atualize a fonte oficial e depois os exemplos.
